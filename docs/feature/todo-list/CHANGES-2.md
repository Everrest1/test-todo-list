# CHANGES-2: Сортировка по дате добавления и фильтр выполненных

- **Статус:** реализовано
- **Связанный план:** [PLAN.md](./PLAN.md)
- **Предыдущая итерация:** [CHANGES-1.md](./CHANGES-1.md)
- **Область:** список задач, управление отображением

---

## 1. Контекст

После базовой реализации и доработки формы потребовалось управлять порядком и составом списка:

1. показывать последние добавленные задачи сверху;
2. дать возможность переключить порядок на «сначала старые»;
3. скрывать выполненные задачи;
4. визуально отделить блок управления от списка и сделать основной контейнер шире, чтобы подписи не переносились.

---

## 2. Требования

### FR-1. Сортировка по дате добавления

- По умолчанию задачи сортируются по `createdAt` по убыванию: **последние — сверху**.
- Пользователь может переключить порядок на **«Сначала старые»**.
- Сортировка применяется к отфильтрованному списку.
- Сортировка не изменяет порядок хранения задач в `localStorage` — это только представление.

### FR-2. Фильтр выполненных

- Пользователь может включить режим **«Скрыть выполненные»**.
- При включённом фильтре в списке остаются только задачи с `completed === false`.
- Если все задачи выполнены, вместо пустого списка показывается сообщение «Все задачи выполнены».
- Если задач нет вообще, показывается «Задач пока нет».

### FR-3. Визуальное отделение блока управления

- Сортировка и фильтр объединены в отдельный контейнер `Paper` с обводкой (`variant="outlined"`).
- Фон блока отличается от фона основной карточки, чтобы блок читался как отдельный элемент.

### FR-4. Ширина контейнера и переносы текста

- Основной контейнер `MuiPaper-root` шире, чем в предыдущей версии.
- Подписи кнопок сортировки и фильтра не переносятся на новую строку.
- На мобильных экранах блок управления по-прежнему перестраивается в колонку.

---

## 3. Решение

### 3.1. Состояние отображения

Состояние сортировки и фильтра хранится в `App` через `useState`:

```ts
const [sortOrder, setSortOrder] = useState<TodoSortOrder>('newest')
const [hideCompleted, setHideCompleted] = useState(false)
```

Это UI-настройки, поэтому они не попадают в Zustand-store и `localStorage`. При перезагрузке страницы снова действуют значения по умолчанию: последние сверху, выполненные видны.

### 3.2. Фильтрация и сортировка

В `App` вычисляется `visibleTodos` через `useMemo`:

```ts
const filtered = hideCompleted
  ? todos.filter((todo) => !todo.completed)
  : todos

return [...filtered].sort((a, b) => {
  const byDate = b.createdAt - a.createdAt
  return sortOrder === 'newest' ? byDate : -byDate
})
```

Исходный массив `todos` не мутируется — перед сортировкой создаётся копия.

### 3.3. Компонент управления

Добавлен `src/components/TodoControls.tsx`:

- `ToggleButtonGroup` с вариантами **«Сначала новые»** и **«Сначала старые»**;
- `Switch` с подписью **«Скрыть выполненные»**;
- на мобильных экранах элементы располагаются вертикально, на `sm+` — в одну строку.

### 3.4. Список задач

`TodoList` стал презентационным компонентом:

- принимает `todos` и необязательный `emptyMessage`;
- больше не читает store напрямую;
- отображает переданное сообщение, когда список пуст.

### 3.5. Версионирование хранилища

`STORAGE_VERSION` **не менялся**, так как схема данных в `localStorage` не изменилась. Сортировка и фильтр — вычисляемое представление, а не новые поля задачи.

### 3.6. Визуальное отделение блока управления

`TodoControls` обёрнут в `Paper` с обводкой:

```tsx
<Paper
  variant="outlined"
  sx={{ p: { xs: 1.5, sm: 2 }, mb: 2, bgcolor: 'background.default' }}
>
```

Это создаёт визуальную границу между формой добавления, блоком управления и списком задач.

### 3.7. Ширина основного контейнера

В `App` контейнер расширен:

- `Container` переведён с `maxWidth="sm"` на `maxWidth="md"`;
- основной `Paper` получил `maxWidth: 760` и центрирование через `mx: 'auto'`.

Для подписей добавлен `whiteSpace: 'nowrap'`, а элементы управления получили `flexShrink: 0`. Поэтому текст в кнопках и фильтре не переносится на другую строку на широких экранах.
