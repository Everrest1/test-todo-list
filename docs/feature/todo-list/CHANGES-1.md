# CHANGES-1: Ограничение длины задачи и адаптивная форма

- **Статус:** реализовано
- **Связанный план:** [PLAN.md](./PLAN.md)
- **Область:** форма добавления задачи (`TodoForm`), store, миграции

---

## 1. Контекст

После базовой реализации To-Do List потребовалось:

1. ограничить длину названия задачи;
2. сделать строку «инпут + кнопка» удобной на узких экранах.

---

## 2. Требования

### FR-1. Ограничение ввода

- Максимальная длина названия задачи — **300 символов**.
- Ограничение действует и на ввод с клавиатуры, и на вставку из буфера обмена.
- Store дополнительно обрезает значение, чтобы ограничение нельзя было обойти через код или миграцию.
- Пользователь видит счётчик введённых символов.

### FR-2. Адаптивная форма

- На экранах шириной меньше `sm` (мобильные) поле ввода и кнопка располагаются вертикально.
- Кнопка занимает всю доступную ширину на мобильном экране.
- На экранах `sm` и шире поле и кнопка располагаются в одну строку.
- Кнопка не сжимается и не переносится на десктопе.

---

## 3. Решение

### 3.1. Единая константа

Добавлен файл `src/constants.ts`:

```ts
export const MAX_TODO_TITLE_LENGTH = 300
```

Константа используется в форме, store и миграциях, чтобы лимит задавался в одном месте.

### 3.2. Форма (`src/components/TodoForm.tsx`)

- У `TextField` задан нативный лимит:

  ```tsx
  slotProps={{ htmlInput: { maxLength: MAX_TODO_TITLE_LENGTH } }}
  ```

- В `onChange` значение дополнительно обрезается:

  ```tsx
  setTitle(event.target.value.slice(0, MAX_TODO_TITLE_LENGTH))
  ```

- Под полем выводится счётчик `текущая_длина/300`.
- `Stack` переведён на адаптивное направление:

  ```tsx
  direction={{ xs: 'column', sm: 'row' }}
  ```

- Кнопка растягивается на мобильном экране:

  ```tsx
  sx={{ width: { xs: '100%', sm: 'auto' } }}
  ```

### 3.3. Store (`src/store/todoStore.ts`)

При добавлении задачи значение обрезается перед проверкой на пустоту:

```ts
const trimmed = title.trim().slice(0, MAX_TODO_TITLE_LENGTH)
if (!trimmed) return
```

Это защищает данные от обхода UI-ограничения.

### 3.4. Миграции (`src/store/migrations.ts`)

При нормализации сохранённых задач название также обрезается до 300 символов. Это гарантирует, что данные, записанные старой версией приложения, не превысят новый лимит.

Версия схемы `localStorage` **не менялась** (`STORAGE_VERSION = 1`), так как структура данных осталась прежней — изменилось только правило валидации.

## 5. Критерии приёмки

- [ ] В поле нельзя ввести больше 300 символов.
- [ ] Вставка строки длиннее 300 символов обрезается до 300.
- [ ] Счётчик показывает корректное количество символов.
- [ ] На мобильном экране поле и кнопка стоят друг под другом, кнопка на всю ширину.
- [ ] На широком экране поле и кнопка стоят в одну строку.
- [ ] Задача длиннее 300 символов, добавленная через store, сохраняется обрезанной.
- [ ] Старые данные из `localStorage` с длинным названием нормализуются при загрузке.
- [ ] `npm run lint` и `npm run build` проходят без ошибок.

## 7. О названии файла

Файл назван `CHANGES-1.md` — это журнал изменений первой итерации после основного плана.

В терминах SDD (Spec-Driven Development) основные артефакты обычно называются `spec`, `plan`, `tasks`. Для точечных доработок удобно вести отдельный журнал `CHANGES-N.md`: он не переписывает исходный план, а фиксирует дельту, причины и критерии приёмки. Альтернативные варианты: `EDITS-1.md`, `CHANGE-REQUEST-1.md`, `SPEC-1.md`.
